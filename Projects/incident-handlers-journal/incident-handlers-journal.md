# Incident Handler’s Journal

This journal documents incident investigations, cybersecurity tool usage, and
professional reflections completed during cybersecurity training. The entries
align with the NIST Incident Response Lifecycle and demonstrate incident response
documentation skills.

---

## Entry #1

**Date:** July 23, 2024  
**Focus:** Documenting a cybersecurity incident  

### Description
This incident occurred during two phases of the NIST Incident Response Lifecycle.
During the Detection and Analysis phase, the organization identified a ransomware
incident and contacted external organizations for technical assistance. During the
Containment, Eradication, and Recovery phase, the organization shut down computer
systems to prevent further damage. Because the organization could not fully recover
on its own, additional external assistance was required.

### Tool(s) Used
- None

### The 5 W’s
- **Who:** An organized group of unethical hackers  
- **What:** A ransomware security incident  
- **Where:** A healthcare company  
- **When:** Tuesday at 9:00 a.m.  
- **Why:** Attackers gained access through a phishing attack and deployed
  ransomware to encrypt critical files. The motivation appeared to be financial,
  as a ransom was demanded for the decryption key.

### Additional Notes
- How could the healthcare company prevent a similar incident in the future?  
- Should the organization pay the ransom to recover encrypted data?

## Entry #2

**Date:** July 25, 2024  
**Focus:** Analyzing a packet capture file  

### Description
This entry documents the use of Wireshark to analyze a packet capture file.
Wireshark is a graphical network protocol analyzer that allows analysts to capture
and inspect network traffic. The tool is valuable in cybersecurity because it helps
identify suspicious or malicious activity by examining packet-level data.

### Tool(s) Used
- **Wireshark**
  - Used to analyze packet capture data
  - Reviewed network protocols and traffic flows
  - Helped visualize and understand network communication

### The 5 W’s
- Not applicable — tool exploration activity

### Additional Notes
This was my first experience using Wireshark. Initially, the interface felt
overwhelming, but I quickly realized how powerful the tool is for understanding
network traffic and investigating potential security issues.

## Entry #3

**Date:** July 25, 2024  
**Focus:** Capturing my first network packet  

### Description
This entry documents the use of tcpdump to capture and analyze network traffic.
tcpdump is a command-line network protocol analyzer that allows security analysts
to capture, filter, and inspect packets in real time. The activity reinforced the
importance of understanding command-line tools in cybersecurity investigations.

### Tool(s) Used
- **tcpdump**
  - Captured live network traffic
  - Filtered packets based on protocol and traffic type
  - Analyzed packet headers and communication patterns

### The 5 W’s
- Not applicable — tool exploration activity

### Additional Notes
Using the command-line interface was challenging at first. I made mistakes with
commands and filters, but by carefully following instructions and retrying steps,
I successfully captured network traffic and gained confidence using tcpdump.

## Entry #4

**Date:** July 27, 2024  
**Focus:** Investigating a suspicious file hash  

### Description
This entry documents an investigation of a suspicious file hash using VirusTotal.
The incident occurred during the Detection and Analysis phase of the NIST Incident
Response Lifecycle. An alert was triggered by security systems, requiring further
analysis to determine whether the file posed a real threat.

### Tool(s) Used
- **VirusTotal**
  - Analyzed a SHA-256 file hash
  - Reviewed community detections and threat intelligence
  - Confirmed the file was malicious

### The 5 W’s
- **Who:** An unknown malicious actor  
- **What:** A malicious file attachment delivered via email  
- **Where:** An employee’s computer at a financial services company  
- **When:** 1:20 p.m., when an alert was generated by the intrusion detection system  
- **Why:** The employee downloaded and executed a malicious email attachment,
  allowing the file to run on the system

### Additional Notes
How can this type of incident be prevented in the future? Should the organization
improve security awareness training to reduce the risk of employees interacting
with malicious email attachments?

## Reflections / Notes

### 1. Were there any specific activities that were challenging for you? Why or why not?
Using tcpdump was the most challenging activity because I was new to the command
line and unfamiliar with the tool’s syntax. Initially, I felt frustrated when my
commands did not work as expected. After retrying the activity and carefully
reviewing instructions, I gained confidence and improved my troubleshooting skills.

### 2. Has your understanding of incident detection and response changed after taking this course?
Yes, my understanding has significantly improved. I now better understand the
incident response lifecycle, the importance of preparation and documentation, and
how tools and processes work together during incident detection, analysis, and
response.

### 3. Was there a specific tool or concept that you enjoyed the most? Why?
I enjoyed learning about network traffic analysis the most. Using tools like
Wireshark and tcpdump to capture and analyze live network traffic was both
challenging and exciting. It helped me see how theoretical concepts apply to
real-world security investigations.
